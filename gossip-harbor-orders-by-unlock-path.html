Segment 1

Fixed onboarding

The scripted opening sequence fills early board slots before normal order traffic.

Inner type Fixed / 0

Fixed onboarding orders

LVPlayer levelEach source row has its own unlock level; the sequence begins at level 1.

Fixed and normal creation overlap from level 3.

At a Glance

  • Sixteen canonical rows form the finite opening sequence.

How It Unlocks

  1. Read the next fixed row.
  2. Meet its row unlock level and fill an eligible listed slot.

How It Creates the Order

  1. Read CurrentFixedOrderId and consider only CurrentFixedOrderId + 1.
  2. Require the current slot in Slots and player level at or above UnlockLevel.
  3. Persist the new CurrentFixedOrderId immediately at creation time, copy up to three requirements, choose an avatar, and return Fixed.

Worked Example

  1. Fixed order 1 unlocks at level 1 in slot 1.
  2. Fixed order 16 is the final canonical row.

Segment 2

Normal orders

Level-gated random families progressively occupy the standard board slots.

Inner type Random1 / 1

Random1

LVPlayer levelPlayer level 3 is required.
Rule detailPoint=5; slots 1–2

At a Glance

  • Normal random family for Low/random pool for slots 1–2.
  • Refresh interval: 3600 seconds.
  • Creator priority tries fixed, return-user, tutorial, continuous, PK1v1, and lucky creators before the standard random creator; the first creator that returns an order wins.

How It Unlocks

  1. Reach level 3.
  2. Read remaining points when the timer is zero. Missing point state uses configured Point (default 1); zero starts a server-time cooldown, while a missing timer or one elapsed by RefreshTime refills points and clears the timer. With points available, decrement and save one point before creation.

How It Creates the Order

  1. Choose the active rule family and first matching filter row, then build the eligible candidate pool.
  2. Apply relative weight candidate.Weight × contextMultiplier, then effective weight (baseWeight × contextMultiplier × dynamicMultiplier) / repeatPenalty; weighted-select the first candidate and rebuild the pool for later candidates.
  3. Select requirement count from valid rule-local ItemAmounts or the highest matching OrderItemNumberWeightConfig row, limited to counts whose candidate exists.
  4. Create the order in its assigned slot.

Worked Example

Source-backed

  1. The canonical Random1 rule unlocks at level 3.
  2. Point=5; slots 1–2

Rewards & Delivery

  • Calculate price = Σ requirementConfig.Price and primary reward ceil(price × goldMultiplier), then apply configured additional rewards and runtime reward-system extras.
  • On delivery, verify exact item codes and preserve repeated occurrences; consume board items before inventory items, recount after each removal, run reward-system events, and ask the owning model to finish, log, remove, and refill before emitting FinishOrder.
Edge Cases & Evidence Limits
  • Candidate exclusions and repeat-chain penalties can prevent a particular item from being selected.

Designer Takeaway

This family adds a predictable board position at a named player-level gate.

Programmer Notes

Use the canonical defaultRandomRules row keyed by innerTypeId; do not infer a rule from slot number.
